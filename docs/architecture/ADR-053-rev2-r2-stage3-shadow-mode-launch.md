## 度量基础设施接地(诚实区分"复用现有"与"新建")

rev2 的两个 P0 闭合必须接地到真实能力。经代码核实:

| 能力 | 现状 | rev2 用途 | 落地归属 |
|------|------|----------|---------|
| AHIRT `RedTeamAudit` / `AhirtProbeCompleted`(event-bus) | ✅ 事件存在(parliament L8 发布);gsoe 现有 `handle_red_team_audit` 手动处理器**语义为"提升变异率",非门禁** | 外部正交对抗信号(决策 3A″/5′)—— **门禁语义"发现=0"需新接线** | 复用事件 + 新接线 |
| `ExecReport.coverage` + `check_real_execution`(pvl-layer 防硬编码 Process-Score) | ✅ 存在 | 覆盖率维度 + 防"硬编码通过"(决策 3A″) | 复用现有 |
| `FitnessReport.fitness_score`(gsoe,`(reward+1)/2` 占位内部奖励) | ✅ 存在但是**内部信号** | **明确不作外部证据**(奖励黑客脆弱) | 排除 |
| 变异测试(mutation testing,如 cargo-mutants) | ❌ 无 | 测试套件充分性度量,检测过拟合(决策 3A″) | **阶段③ 启动前新建** |
| held-out 对抗任务集(进化期未见任务) | ❌ 无 | 检测测试套件过拟合(决策 3A″) | **阶段③ 启动前新建** |
| 统计检验(binomial / block bootstrap / Mann-Kendall) | ❌ 无 | 有效样本量修正 + 阈值重校(决策 3A′) | **阶段③ 启动前新建** |

> 规格与验收标准。这是诚实声明,非既成能力。

## 决策 3A′:闭合 E06 N-1 —— 独立批次 + 配对设计 + 阈值重校

**根因(E06 N-1)**:R1 的 0.714 = "14 个**日历日**中 ≥10 天胜",其 p<0.05 二项检验
成立的前提是**日间独立**。但 R2 是进化谱系——一个变体产生后跨多日持续存在,使
"日胜负"强正自相关,有效样本量 N_eff ≪ 14,朴素二项检验的名义 5% I 类错误率被
严重低估。**直接移植 0.714 到 R2 是统计学误用**。

**闭合方案**——把独立性单元从"日历日"改为"独立评估批次",并重校阈值:

1. **独立评估批次(replace 日历日)**:定义比较单元为 **独立任务队列(batch)**——每批
   用一组**无变体结转**的全新任务,批次间无谱系延续,恢复独立性。晋级要求 **≥14 个
   独立批次**(非 14 个日历日),消除自相关。

2. **配对比较设计(降方差)**:每批中 R2 影子与冻结 L3 基线**跑同一任务集**(paired),
   单批"胜负"= 配对差值符号检验。配对设计消除任务难度的批间方差,提升检出力。

3. **单批胜负判定(补齐 rev1 缺失定义)**:沿用 R1 `ComparisonResult` 五档思路,以
   **外部复合得分**(决策 3A″,非内部 fitness)差值判定:差值 ≥ +ε_win 计胜、
   ≤ −ε_win 计负、中间为平局。**平局与样本不足批次按 fail-closed 计"非胜"**(不剔除,
   保持分母稳定——剔除会让分母浮动使二项检验失效,这正是 rev1 的漏洞)。

4. **阈值重校(替代盲目移植 0.714)**:用 **block bootstrap** 对批次序列估计 N_eff 与
   胜率的置信区间,晋级要求胜率 CI 下界 > 0.5(而非固定 0.714)。若批次确证独立
   (设计 1 保证),则退化为标准二项,0.714 仍适用;若残留自相关,bootstrap 自动收紧。

## 决策 3A″:闭合 E02 N-1 —— 多维复合外部门(反过拟合)

**根因(E02 N-1)**:测试通过率是**有限覆盖代理**,R2 可能生成"过拟合现有测试套件、
覆盖盲区实质有害"的变体——这是 rev1 对伪 regret 的批评在更外一层的复现。

**闭合方案**——外部证据门从"单维 pass_rate"升级为**四维正交复合**,变体须**同时**
满足(任一维失败即该批非胜),迫使奖励黑客攻破多个正交面:

| 维度 | 度量 | 阈值 | 抗过拟合原理 | 落地 |
|------|------|------|-------------|------|
| ① 测试通过 | `ExecReport.pass_rate` | ≥0.9 | 基础功能正确 | 复用 |
| ② 真实执行 | `check_real_execution`(耗时>10ms ∧ coverage>0) | true | 防"硬编码通过" | 复用 |
| ③ 测试充分性 | 变异测试得分(mutation score) | ≥ 基线 | 弱测试套件杀不死变异 → 检出过拟合 | 新建 |
| ④ 未见任务 | held-out 对抗集胜率 | 计入 3A′ | 进化期未见 → 骗不过 | 新建 |
| ⑤ 外部对抗 | AHIRT `RedTeamAudit` 新增发现 | **探测量≥N_probe 且发现=0** | 红队独立探测有害变体 | 复用事件+新接线 |

**关键**:①② 复用现有(但 ①pass_rate 与 ②真实执行来自**同次沙箱执行、非正交**,
按单一"执行面"计权、不虚增维度数);⑤ 复用 AHIRT 事件但**门禁语义需新接线**
(现有处理器仅提升变异率);③④ 是新建工程。外部复合得分(喂给 3A′ 单批判定)=
上述维度的加权,**须声明每维非零最小权重下界**(防某维权重→0 使复合门退化为单维);
**权重与具体公式列为阶段③ 启动前 + E06/E02 联合评审项**(避免拍脑袋定权重,重蹈
"未论证移植"覆辙)。

## 决策 5′:验证器游戏化防御补强(叠加 rev1 决策 5)

rev1 决策 5 的三层防御(外部门主防线 + 人工抽样 + 属性集冻结)保留,rev2 补强:

- **held-out 盲区探测**(补 E02 3.2):人工抽样审计**不只审变体本身,须含"测试盲区
  探测"**——主动构造现有测试未覆盖的对抗输入,检验变体在盲区的行为。
- **变异测试作为套件充分性哨兵**:mutation score 持续下降 = 测试套件被侵蚀,触发告警。

## 继承 rev1 的决策(不变,不重复正文)

- **决策 2**:影子副本隔离(Allowed=记录对比,永不写生产谱系)—— 不变
- **决策 4**:ShadowModeOrchestrator @ L9 —— 编排器骨架不变;但 rev2 五维门的 ①②
  数据(`ExecReport`)在 pvl-layer(**L7**)、⑤(AHIRT)在 parliament(**L8**),故
  **依赖清单在 rev1 的 L6/L5/L4/L1 基础上扩至 L9→L7 / L9→L8(均向下,合规)**;
  **关键**:变体门判定须由 **L9 编排器居中直读 L7/订阅 L8**,gsoe(L5)**不得直接
  消费 pvl(L7)**(否则 L5→L7 向上依赖违规,R2-E01-2)
- **决策 6(更新自 rev1)**:晋级门 = **≥14 独立批次**(替代"≥14 日历日")+ **外部
  胜率 bootstrap CI 下界>0.5**(替代固定 0.714)+ 负面异常门未触发 → ADR-054。
  **rev1 的"≥14 天 + 0.714"因 3A′ 闭合 E06 N-1 而失效,此处为实质更新,非不变**

## 残留条件项(P1/P2,归阶段③ 启动工程,非本 ADR 阻断)

通道防篡改、预热与胜率窗关系、观察期上限)**保持在册**,归入阶段③ 启动 runbook +

## 后果

**正面**:
- E06 N-1 闭合:独立批次 + 配对 + bootstrap 重校,使"胜率门"统计前提在 R2 语境成立,
  不再是 R1 阈值的误用移植
- E02 N-1 闭合:四维正交复合门迫使奖励黑客同时攻破功能/覆盖/变异/未见/对抗五面,
  单维过拟合不再能骗过晋级
- 诚实接地:明确 3 项新建工程的规格与归属,不把"待建能力"伪装成"已就位"

**负面/风险**:
- 独立批次 + 配对 + 变异测试 + held-out + AHIRT 五信号,阶段③ 启动工程量显著增加
- 外部复合得分的权重公式仍需 E06/E02 联合评审确定(rev2 只定框架不拍权重)
- 变异测试对 Rust 进化变体的算力开销需评估(cargo-mutants 全量变异较慢)
