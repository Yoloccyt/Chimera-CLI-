# ADR-297: R12 W2 —— 记忆层检索路径的边界订正（建图阈值断续）+ 一条被驳回的定性

- 状态: Accepted
- 日期: 2026-11-14
- 批次: R12 W2（八波次计划的第三波；W0/W1 见 ADR-296 与 `r12-w1-1` 报告）
- 关联: ADR-296(R12 W0 度量地基) / ADR-289(R8 记忆层热路径削减) / ADR-192(mlc L2 分层检索) / `agents.md §4.4` async 反模式清单
- 影响面: `crates/mlc-engine/src/memory_graph.rs`、`crates/mlc-engine/benches/memory_graph_edges.rs`

---

## 1. 背景：一个"规模翻倍反而快 4 倍"的读数

R12 W0 取基线时，`target/criterion` 存档里同一组基准的三档读数**非单调**：

| 节点数 | 存档中位数（2026-11-12） | 说明 |
|---|---|---|
| 1000 | **426.88 ms** | 精确路径 `O(n²·512)` |
| 2000 | **102.20 ms** | HNSW 候选路径 |
| 10000 | 634.15 ms | HNSW 候选路径 |

1000 比 2000 慢 **4.2×**。这不是噪声（同组三档都跑了 10 样本），也不是"算法非线性"，而是**判据的位置问题**：

```rust
// 订正前（crates/mlc-engine/src/memory_graph.rs:154）
if ids.len() > HNSW_SWITCH_THRESHOLD {   // HNSW_SWITCH_THRESHOLD = 1000
    self.build_semantic_edges_hnsw(&ids, threshold);
} else {
    self.build_semantic_edges_exact(&ids, threshold);
}
```

`>` 把 `n == 1000` 恰好划到精确侧 ⇒ 阈值点本身是**全曲线最慢的点**。常量处原注释已记录"1K=464ms（可接受）"，但"可接受"是对绝对值说的，**没有人检查过它与 2000 的单调性**——这正是 R12 W0 立"先取基线"这条的原因。

---

## 2. 决策

### D1 —— 判据由 `>` 改为 `>=`，并把路由抽成可测纯函数

```rust
/// 规模路由判定 —— 纯函数,使"在阈值点走哪条路"可被结构测试直接钉住
#[inline]
fn uses_hnsw(node_count: usize) -> bool {
    node_count >= HNSW_SWITCH_THRESHOLD
}
```

`build_semantic_edges` 改为调用它。**WHY 抽函数**：原实现把判据内联，`>` 与 `>=` 的差别只能靠"建边结果的近似差异"间接观察（不可靠，且当图恰好稀疏时两边边集可能相同 ⇒ 测试恒绿）。抽出来后判据本身可被直接断言。

两条互为阳性对照的单测（`crates/mlc-engine/src/memory_graph.rs` 内）：

| 用例 | 断言 | 作用 |
|---|---|---|
| `threshold_point_uses_hnsw` | `uses_hnsw(1000) && uses_hnsw(1001)` | 钉住边界归 HNSW；改回 `>` 立刻红 |
| `threshold_minus_one_stays_exact` | `!uses_hnsw(999)` | **阳性对照**：证明上一条不是"恒真"（若判据被写成 `true`，本条红） |

### D2 —— 基准增加 999 / 1000 / 1001 三档，把残余断崖**显形**

`crates/mlc-engine/benches/memory_graph_edges.rs` 的规模序列由 `[1000, 2000, 10000]` 扩为 `[999, 1000, 1001, 2000, 10000]`。

**WHY 不是只加 1000**：只改判据而不把 999 摆在旁边，等于把断崖从 1000 挪到 999 后假装曲线连续了。三档并排，读者一眼能看见"999 仍是 557ms、1000 是 79ms"——**残余缺口是测量出来的一等事实，不是注释里的形容词**。

### D3 —— 否决"顺手把阈值下修到 256~512"（本波做、但只做一半）

按本节 §4 的实测曲线外推，把阈值下修到 ~256 能把最坏点从 557ms 压到 ~36ms（约 −93%）。但：

- 它改变 `n ∈ (新阈值, 1000)` 区间的**建边语义**：精确全对 → HNSW 近似候选；
- 模块头注释已声明"建边候选可接受近似"，但那是**对大规模**说的；把小规模也切到近似，等于扩大了一条既有裁定的适用范围，**属行为变更**，须独立裁决（R12 计划里 Q3 同族：不擅自降级语义换性能）。

故本波只交付**边界订正 + 裁决输入数据**，不动阈值数值。重开条件：若下游出现 500–1000 节点规模的图谱且建边延迟进入 p95 观测面，按 §4 曲线另行裁决。

## 3. 一条被驳回的定性（重要：这是对我方自己审计结论的纠错）

R12 的现状证据章（`docs/architecture/_blueprints/toolchain-r12/02-现状证据-上下文与记忆层.md` §0.1②）把
`recall_by_clv` 在 `read()` 锁内做全量余弦判定为违反 `agents.md §4.4` 反模式 1。

**本 ADR 驳回该定性**，理由是可核对的原文与代码事实：

1. `§4.4` 反模式 1 的标题是 **"禁止持锁跨 `.await`"**，正文是"DashMap/Mutex 写锁必须在 `.await` 前释放"。它约束的是 **async 上下文里的锁持有跨度**，不是"持锁做 CPU 计算"。
2. `recall_by_clv`（`crates/mlc-engine/src/l2_semantic.rs:544-573`）是**同步函数**，全程无 `.await`；其内部 `recall_exact` / `recall_approx` 也是同步纯计算。把 §4.4 #1 套到这里，是把一条 async 纪律误用到 sync 路径上。

**但驳回定性不等于登记无事**：读锁持有期间写者（`insert`/`remove`）确实被阻塞，这属于**锁竞争**问题，其严重性取决于"读并发度 × 读持有时间 vs 写频率"，**本波没有测，故不声称已修、也不声称无害**。登记为开放项：

- 需要的证据：一个 `N 读 + 1 写` 的并发基准（写者获取写锁的 p95 延迟 vs 读者数）；
- 若 p95 随读者数线性劣化 ⇒ 才值得做"锁外快照"（把 `vectors` 移到 `Arc<[...]>` 做 COW，代价是插入时 `make_mut` 的克隆）；
- 本波不做，因为**在没有读-写竞争证据前改锁结构，是用正确性风险换一个未证明的问题**。

> **【2026-11-14 更新：本判据已被实测推翻，由 ADR-299 §2.5 替代】**
> `crates/mlc-engine/benches/l2_lock_contention.rs`（ADR-299 W2-2）实测三次，结论：
> ① p95 **非单调**（峰在 c=4、c=8 回落），"随读者数线性劣化"这一前提**事实不成立**；
> ② 罚金有界：归一化后 p50(c=8) = 1.1~1.4 × H、p95 = 2.3~5.9 × H（H = 一次召回持锁时长 4.33~5.17 ms）；
> ③ 修法（锁外克隆）**无条件成本 9~35×** 无竞争插入，而收益只在碰撞时兑现 ⇒ **判定不改锁**。
> 替代判据（p95 ≥ 3×H / 读占空比 ≳20% / 生产占空比必须实测）见 ADR-299 §2.5。

## 4. 验收（机证）

| 判据 | 命令 | 实测 |
|---|---|---|
| 边界单测（含阳性对照） | `cargo test -p mlc-engine --lib memory_graph --jobs 2` | `9 passed; 0 failed`（含新增 2 条） |
| clippy 零告警 | `cargo clippy -p mlc-engine --all-targets --jobs 2 -- -D warnings` | rc=0 |
| 格式 | `cargo fmt -p mlc-engine -- --check` | rc=0 |
| 规模曲线（同轮） | `cargo bench -p mlc-engine --bench memory_graph_edges` | 见下表 |

**建边规模曲线（本机本轮，`--measurement-time 1.0`，10 样本）：**

| n | 路由 | 中位数 | 相对 999 |
|---|---|---|---|
| 999 | 精确 `O(n²·512)` | **557.32 ms** | 1.00× |
| 1000 | HNSW（订正后） | **79.01 ms** | **0.14×**（快 7.05×） |
| 1001 | HNSW | 80.01 ms | 0.14× |
| 2000 | HNSW | 150.84 ms | 0.27× |
| 10000 | HNSW | 946.50 ms | 1.70× |

**读法**：
- 阈值点从 557ms 量级降到 79ms 量级（**7.05×**），且 1000 / 1001 两档基本相等 ⇒ 订正生效且未引入新的边界效应；
- HNSW 侧近线性：1000→2000 为 1.91×、2000→10000（5× 节点）为 6.27× ⇒ 与 `O(n·log n)` 相符；
- **残余断崖仍在 999**（557ms），本 ADR 不掩盖它（见 D3）。

> 存档对照：2026-11-12 存档记 `1000=426.88ms`，本轮同点订正后 `1000=79.01ms`。两个数不同机时、不同负载，**不比绝对值，只比路由归属**（前者精确、后者 HNSW）。

## 5. 回滚

- 单 commit revert 即可（判据一行 + 抽函数 + 两条单测 + 基准三档）。
- 无 env 开关：本改动不引入运行时行为分支，只改"在阈值点走哪条既有路径"，且两条路径都是既有实现、都有既有测试覆盖。
- 若下游依赖"1000 节点仍走精确路径"的边集**完全一致**，回退判据为 `>` 即可，但需同时删掉 `threshold_point_uses_hnsw`（否则该测试会红——这是刻意的：**回退必须显式，不能静默**）。

## 6. 减法（本波明确不做）

| 不做 | 理由 |
|---|---|
| 阈值下修到 256~512 | 改变建边语义，属独立裁决（§2 D3） |
| `vectors` 迁到 `Arc` 做锁外计分 | 缺读-写竞争证据；改锁结构有正确性风险（§3） |
| 给 `recall_by_clv` 加超时/取消 | 同步纯计算，无可取消点；加了也是假的 |
| 改既有 `memory_graph_edges` 的 2000/10000 档 | 它们是对照档，改动会破坏与历史存档的可比性 |
