## 背景

ADR-042 定义 R2(GSOE×AutoDPO 约束 RL)解冻三阶递进。截至 2026-07-29:

| 阶段 | 内容 | 状态 |
|------|------|------|
| ① FormalVerifier 落地 5 判定标准 | M0/M1/M2 7/7 属性 | ✅ 达成(ADR-052 §盘点) |
| ② 工程前置 + 解冻 ADR 评审 | 4 前置 + capstone 代码就位 | ✅ 前置就位 / ⏳ 本 ADR 即评审载体 |
| ③ 影子模式 2 周观察 | 需真实运行数据 | ❌ 本 ADR 定义启动方案 |

阶段② 的 4 前置 + capstone 已代码化并全绿(f42e072 / 138b3a5 / c42e83c /
0f8ae0f / 89dcd56)。本 ADR 是阶段② 的**解冻 ADR 评审载体**,同时定义阶段③
影子模式的启动方案与量化异常阈值。

## 本 ADR 明确不做(边界声明)

1. **不解冻 R2**:CI 的 5 关键词扫描(`constrained_rl` / `r2_policy` / `train_r2` /
   `GsoeAutoDpoRL` / `evolve_with_constrained_rl`)在本 ADR 批准后**继续生效**,
   直至阶段③ 观察期满且三方复核通过,另立解冻执行 ADR(ADR-054)。
2. **不启动影子模式**:本 ADR 是启动**方案**,启动动作需三方评审联签 + 用户授权。
3. **不接线 RL 路径**:各前置与真实 RL 更新路径的埋点接线属阶段③ 启动后动作。
4. **不含关键词代码**:本文档仅在背景引用处以反引号包裹说明 5 关键词,非代码标识符。

## 决策(提案,待三方评审)

### 决策 1:影子模式启动前置门(全部满足方可启动)

| 前置门 | 验证方式 | 当前状态 |
|--------|---------|---------|
| G1 FormalVerifier 7/7 属性 | `formal_verifier_{e2e,m1_e2e,m2_e2e}` 全绿 | ✅ 91 E2E 全绿 |
| G2 后悔率采集就位(前置1) | `RegretCollector` + regret_collection_e2e | ✅ |
| G3 CI 门禁就位(前置2) | `FormalVerifierGate` + gate_e2e | ✅ |
| G4 熔断器就位(前置3) | `ShadowModeCircuitBreaker` + breaker_e2e | ✅ |
| G5 范围守卫就位(前置4) | `UnfreezeScope` + scope_e2e | ✅ |
| G6 统一决策闸门(capstone) | `UnfreezeGovernor` + governor_e2e | ✅ |
| G7 R2 冻结守护未破坏 | `r2_freeze_violation_e2e` 22 全绿 | ✅ |
| **G8 三方评审联签** | 架构/安全/认知签署本 ADR | ⏳ **待评审** |

### 决策 2:影子模式解冻范围(最小起步,渐进扩大)

依据前置 4 `UnfreezeScope` 的 fail-closed 白名单,阶段③ **仅纳入风险最低的单一
目标起步**,严禁一次性放开:

| 阶段③ 子阶段 | 纳入范围 | 理由 |
|-------------|---------|------|
| ③-a 首 7 天 | 仅 `GsoeVariantSelection` | 变体选择可回滚,无偏好污染风险 |
| ③-b 次 7 天 | 若 ③-a 无异常,追加 `SeamPolicy(4)` | S4 权重系数,已有 R1 先例 |
| ③-c(推迟) | `AutoDpoPreference` | 偏好更新风险最高,推迟至独立 ADR |

### 决策 3:量化异常阈值(接地 ADR-043 R1 先例,R2 从严)

> R2 风险高于 R1,阈值**不低于** ADR-043 R1 影子模式(`shadow_mode.rs` 常量)。

| 指标 | R1 先例(ADR-043) | **R2 提案(从严)** | 触发动作 |
|------|-------------------|---------------------|---------|
| 观察期 | 14 天 | **≥ 14 天**(每子阶段独立计) | 未满不得晋级 |
| 熔断器跳闸 | — | **0 次容忍**(任一 Violated 即跳闸) | 立即中止 + 重冻结 |
| 后悔率趋势 | EWMA 崩塌 ≥0.3 | **assess_trend 不得 Violated** | 中止 |
| CI 门禁违规 | — | **每次进化提交 0 FormalPropertyViolated** | 阻断该提交 |
| 连续退化天数 | 3 天 | **1 天**(R2 从严,单日显著退化即中止) | 中止 + 重冻结 |
| 范围越界 | — | **0 次**(governor Denied(OutOfScope)即告警) | 告警 + 审计 |

### 决策 4:中止与重冻结协议(fail-closed)

阶段③ 期间**任一异常阈值被触发**,执行:
1. `ShadowModeCircuitBreaker` 永久跳闸(不可逆直至人工复核)
2. `UnfreezeScope` 立即 `revoke` 全部目标 → 回到 `frozen()` 全冻结
3. 发布 `NexusEvent::R2FreezeViolation` Critical 告警(走 mpsc 旁路)
4. 事故复盘 + 阈值/前置修正后,重新走决策 1 前置门

### 决策 5:观察期满后的晋级门(进入 ADR-054 解冻执行)

③-a + ③-b 各满 14 天且**全程零异常触发**,方可另立 **ADR-054** 三方复核决定
是否正式解冻(移除对应范围的 5 关键词扫描豁免)。**本 ADR 不含晋级批准**。

## 后果

**正面**:
- 阶段③ 启动条件与量化阈值明确、可证伪(接地 ADR-043 先例,非主观)
- 渐进解冻(单目标起步)+ fail-closed 中止协议,将 R2 风险控制在最小面
- 4 前置 + capstone 代码就位使阈值可自动监测(非人工判断)

**负面/风险**:
- 阶段③ 需真实运行数据 + 14×2 天观察,周期长(设计使然,安全优先)
- 阈值从严可能导致晋级缓慢——这是审慎权衡,R2 奖励黑客风险高于晋级速度
