# R12 · 波次实施与回滚矩阵

- 批次：R12（八波次，W0~W7）
- 组织原则：**一个 WP = 一个原子 commit = 一个可独立 revert 的回滚单位**
- 排序原则：① 先补度量地基；② 先做**零冲突面**（上下文/记忆）；③ 调度面**先合流、不重写**
- 每波五件套：代码 + 测试 + 基准 + 门 + 报告段落，缺一不算完成
- **判据分层**：本批所有性能结论按 `L1 结构判据 > L2 运行时计数器 > L3 比值墙钟 > L4 criterion 阈值` 取用
  （该分层原典在未合并分支 `ADR-234:30-41`，主线无此档，见 W0-3）

---

## 0. 波次依赖图与顺序理由

```text
W0 度量地基 + 合流裁决 + 口径收口
 ├─► W1 上下文装配内核接线 ──┐
 ├─► W2 记忆检索锁外化     ──┼─► W7 收口
 ├─► W3 跨会话一致性       ──┤
 ├─► W4 调度面合流（不重写）─┤
 ├─► W5 AccessSet 冲突感知 ──┤
 └─► W6 跨面资源治理       ──┘
```

**为什么这个顺序**（三条实测依据，不是偏好）：

1. **上下文装配内核在生产上不可达**：`assemble_context` 全仓 19 处命中 = 定义 1 + `lib.rs:86` 重导出 1 + **`tests/assembly_contract.rs` 17 处测试**，
   零生产调用点。R11 的 M4a/M4b（规范化去重、CLV 语义折叠）都落在这一层 ⇒ **调它的参数不可能降低生产冗余**，必须先接线（W1）。
2. **调度线 5 个目标文件与未合并分支全部冲突**，且分支已有"依赖就绪即派发"的完整实现与机证（`ADR-233` 追加节一 W1a、追加节九）。
   R12 若重写就是第二套实现 ⇒ 只做合流与增量（W4/W5/W6）。
3. **记忆层有两个纯代码缺陷**（锁内计算、阈值不连续），不依赖任何外部条件，可立即改（W2）。

**W0 必须写进报告的四个坑（否则后续数字全部不可信）**：

1. `target/criterion/<group>/<bench>/new/estimates.json` **跨会话持久**。实测：本轮只跑 `tool_dispatch_layers`，
   目录里同时存在 `toolplan_layers`（2026-11-12 21:14）、`tool_batch`（2026-11-12 21:14）、`l2_knn_slo`（2026-11-12 08:08）等旧存档 ⇒ 取数先看 mtime。
2. criterion 的 `change:` 是**跨会话比对**，不是同轮对照。本轮 `chain_*` 显示 `+39%~+131%` 回退，实为机器高负载漂移；
   同轮对照（`sandbox_check_seccore` 819.57ns vs `legacy` 5.52µs）才是有效证据。
3. **冷启动首轮比后三轮高 29–43%**（`ADR-234` 实测，未合并分支）。新基准首跑只能当"量级锚"。
4. `perf_thresholds.toml` 的 `tui_tick_bench` 每夜真跑却**无阈值键**（`perf_redlines.toml` 无对应项）——"跑了不断言"，R12 要么补键要么登记为不变量，不许保持中间态。

## W2 · 记忆检索：锁外计算 + 阈值不连续

| 项 | 内容 |
|---|---|
| 目标 | 修两个**已被代码证据定位**的缺陷，而不是泛泛"优化检索" |
| 缺陷 1（锁内计算） | `recall_by_clv` 持 `self.inner.read()` 读锁，在该借用下遍历全部向量算余弦（`crates/mlc-engine/src/l2_semantic.rs:550-553` → `:560` + `:1029-1039`）；近似层候选重算与补口全扫同样在读锁内（`:562`→`:775`、`:781-794`）。**违反 `agents.md §4.4` 反模式 1** |
| 缺陷 2（阈值不连续） | `memory_graph` 用 `ids.len() > HNSW_SWITCH_THRESHOLD(1000)` 选路（`crates/mlc-engine/src/memory_graph.rs:39`、`:154`）⇒ **恰好 1000 条目走 O(n²·512) 精确路径**，2000 反而快 4 倍（存档：1000=426.88ms / 2000=102.20ms / 10000=634.15ms）。这不是噪声，是分支不连续 |
| 改动文件 | `crates/mlc-engine/src/l2_semantic.rs`、`memory_graph.rs`、`benches/memory_graph_edges.rs`、`tests/hnsw_tiered.rs` |
| 修法 1 | 锁内只做 `Arc<Vec<Entry>>` 快照（`Arc::clone` 后立即 `drop(inner)`），余弦计算在锁外；与 `faae-router` 的 `ScoreInput` 快照先例同法（`crates/faae-router/src/parallel.rs:79-92` 注释："由主线程异步读锁收集,评分阶段无锁无 await"） |
| 修法 2 | 阈值改 `>=` 并把 1000 档纳入 bench；或把精确路径的复杂度降到 `O(n·512 + n log n)`（先 `select_nth` 再算候选余弦）。**二选一由 W2 实测裁决**，不预设 |
| 测试 | `hnsw_tiered.rs` 既有 9.8×/22.4× 断言不回退；新增 `recall_lock_not_held_during_scoring`（用 `try_write()` 在评分期间探测锁空闲）；`graph_build_monotonic`（1000/2000/10000 三档单调或平台化，禁止倒挂） |
| 量化指标 | ① **L2**：评分期间 `try_write()` 成功次数 > 0（结构判据，非耗时）；② **L4**：`memory_graph_build_semantic_edges/1000` ≤ 存档 426.88ms × 0.5；③ `l2_knn_slo/top10_recall/10000` 不回退 >10% |
| 采集命令 | `cargo bench -p mlc-engine`；`cargo test -p mlc-engine --test hnsw_tiered --test recall_budget_test` |
| 回滚 | 修法 2 带 `CHIMERA_GRAPH_HNSW_MIN`（默认 1000）；修法 1 无开关但可用单 commit revert |
| 备注 | 本波**允许"零改动"结论**（若实测证明阈值不连续无害）。诚实登记为"已评估不采纳"，不制造伪改动 |
