# R12 · 验收测试与量化指标

- 目的：把"每个阶段配套测试用例、性能指标、量化验收标准"落成**可机判**的条目
- 依据：判据分层沿用 `ADR-234 §2 A1`（原典在未合并分支，主线无此档；本批将其主线化）
- 原则：**测试绿 ≠ 性能好**；**criterion 单次读数 ≠ 结论**；**L2/L3 不得冒充 L4**

---

## 1. 判据四层（取用优先级固定）

| 层 | 判据 | 能证 | 不能证 | 本批用在哪 |
|---|---|---|---|---|
| **L1 结构判据**（首选） | 上界成立 / 完成序重叠 / 阳性对照（改坏必红） | 并行结构成立、屏障消失、上界未破 | 快了多少 | W1/W4/W5/W6 的主判据 |
| **L2 运行时计数器** | `inflight_peak`、`waiters`、`oversubscription_bp`、`try_write()` 成功计数 | 方向性不等式、锁是否空出 | 毫秒收益 | W2/W6 |
| **L3 比值型墙钟** | 同轮 A/B 的 makespan 比、token 装载量 | 结构性变化 | 绝对延迟、跨机可比 | W1/W4/W5 |
| **L4 criterion 阈值** | `perf_thresholds.toml` + CI 首跑校准 | 无回退、幅度 | 一次本地读数定阈值 | W2 的图建基准 |

**合法动作只有两个**：登记"未验"，或先补判据再宣称。
**禁止**：用 L2/L3 冒充 L4；用"测试全绿"顶替 L1。

---

## 2. 明令禁止的四种证明方式（沿用 ADR-234 A2，本批强化）

1. 用**合并高水位**（如 `SchedSnapshot::peak_in_flight` 两车道合并）证"某条车道没被钉住" ⇒ 量不可分解。
2. 用「bench X 前后相等」证「改动 Y 无成本」，**当且仅当** X 的驱动路径不含 Y ⇒ 必须先证 X 能看见 Y（施加一次已知变异的阳性对照）。
3. 用**两侧都失败**的命令做不对称判据（被 `.gitignore` 的文件之于 `git ls-files`）。
4. 用 flaky 计时断言当用例断言 ⇒ 用例只断言**形状**（上界/存在性/顺序），墙钟只进报告。

> 本仓已实锤过的实例：`target/criterion` 跨会话持久导致的"假基线"；`shutil.copy2` 保留 mtime 导致 cargo 复用**变异体二进制**，产生"复原后仍红"的缓存假象。

### 3.1 W1 的三条硬断言

```rust
// tests/wire_off_equals_legacy.rs（新增）
// 1) 关开关时，200 条合成会话的装配输出与旧路径 **逐字节相同**
// 2) 开开关时，输出条数 = 输入条数 - 可折叠条数（精确，不估计）
// 3) 开开关时，剩余条目的 seq 序列是输入 seq 序列的**子序列**（保序）
```

第 3 条是"折叠不得重排"的机器判据 —— 没有它，任何"优化"都可能悄悄改变模型看到的顺序。

### 3.2 W2 的锁空出判据（L2，结构型）

```rust
// 在评分进行中另起线程 try_write()：
// 成功 ⇒ 读锁未在评分期间被持有（修法生效）
// 失败 ⇒ 仍持锁（修法无效，红）
// 阳性对照：故意把快照改回"锁内计算"，该断言必须转红
```

> WHY 不用耗时断言：`l2_semantic` 的评分在 debug/release 相差一个量级，耗时断言在 CI 上必 flaky。

## 6. 度量规约（每次采集必须遵守）

1. **先看 mtime**：`Get-ChildItem target/criterion -Recurse -Filter estimates.json | Sort LastWriteTime -Descending`；
   跨会话存档一律标 `STALE`。
2. **同轮对照**：A/B 必须在**同一进程、同一轮**内跑（criterion 同组两个 `bench_function`），跨轮差值不算因果证据。
3. **冷启动隔离**：首轮只作量级锚（实测高 29–43%），正式读数取第 2–4 轮。
4. **机器负载**：编译/其他重活期间不得采集（本轮实测 `chain_*` 漂移 +39%~+131% 即此因）。
5. **报告句式**（ADR-234 A3 模板）：

   > 「L1 结构判据成立（用例名 + 反证红因）＋ L2 方向性成立；**绝对阈值待 CI 首跑校准**，本地不锁。
   > 全量 heavy 门在本宿主为 `UNKNOWN`（磁盘现取 X GiB < 要求 Y GiB），故不宣称"全门绿"。」

## 7. 回归口径（W7 收口必须一致）

| 项 | 命令 | 说明 |
|---|---|---|
| 全量测试 | `cargo test --workspace --no-fail-fast --jobs 2` | **必须带 `--no-fail-fast`**：不带时首个失败会中止后续 target（实测 447 target 中只跑出 67 行 `test result:`） |
| 触及面 clippy | `cargo clippy -p <crate> --all-targets --jobs 2 -- -D warnings` | 全仓 clippy 有 OOM 风险（`.cargo/config.toml` 的 `jobs = 4` 是根因，命令面覆盖） |
| 格式 | `cargo fmt -p <crate> -- --check` 逐包 | Windows 长路径会让 `--all` 报 `os error 206` |
| 基线对比 | R11 收口：570 targets / 12389 passed / 2 failed | failed 不增即达标；2 红即 W0-3 的收口对象 |

### 9.2 行号复核的方法学坑（写给后来者）

**PowerShell 的 `(Get-Content $f)[$i]` 与真实行号存在偏移**（BOM/行尾混用），本轮用它做抽查时出现了"引用的行号指向别的内容"的假警报，
改用 `read` / `ReadEvidence` 后 12 处全部一致。**复核行号必须用与作者相同的工具链**（`read`/`grep`），不要用索引取行。
