## 3. 核心结论（14 条硬事实，均可独立复核）

### 3.1 性能到底慢在哪

| # | 结论 | 数值 / 证据 |
|---|---|---|
| F1 | 单次工具派发的**固定成本** 1.06 µs；传输地板 80.58 ns | 本轮同轮实测（2026-11-14） |
| F2 | 沙箱门此前已做 6.74× 优化 | 819.57 ns vs legacy 5.52 µs（同轮对照） |
| F3 | 毫秒级工具下，链路开销占比 ≈ **0.003%** | 由 F1 + MCP 2PC 30.67 ms 推出 |
| F4 | **批量并行已达理论上限** | 64×1ms：998.81 ms → 125.36 ms = **7.97×/8×**（效率 99.6%） |
| F5 | 但零延迟任务下并行**反而更慢** | 44.41 µs → 51.27 µs（+15%） |
| F6 | 单层只读并发也已到上限 | 8×2ms：124.42 → 15.66 ms = **7.94×** |
| F7 | 混层写屏障分段有效 | 7 读 1 写：**3.98×**（结构上限 4×） |
| F8 | MCP 2PC 多参与者**已并行** | 1/3/5 参与者：30.67 / 30.74 / 31.24 ms（墙钟 ≈ max 而非 Σ） |

⇒ **"提高并发数"不是题目**：单层/单批已打到硬件与结构上限，再调大只会过订阅。

## 4. 方案骨架（八波）

| 波 | 主题 | 主判据 | 回滚单位 |
|---|---|---|---|
| W0 | 度量地基 + 合流裁决 + 口径收口 | `unknown == 0`；2 红测试清零或登记 | 2 个 commit |
| W1 | 上下文装配内核**接线** | 输出为输入 `seq` 的保序子序列；关闭开关逐字节等价旧路径 | 2 commit + env |
| W2 | 记忆检索：锁外化 + 阈值连续 | 评分期间 `try_write()` 成功 > 0；`build(1000)` ≤ 存档 ×0.5 | 2 commit + env |
| W3 | 跨会话一致性 | 灌 1 万条 → 强杀 → 重启零缺口 | 2 commit + env |
| W4 | 调度面**合流（不重写）** | `plan_runner_eager` 10 例 + 4 变异；偏斜 ≥4× 时 makespan −20% | 1 commit |
| W5 | `AccessSet` 冲突感知（默认关） | 写不相交峰值 >1；写冲突恒 1 | 2 commit |
| W6 | 跨面资源治理 | `oversubscription_bp ≤ 1000` | 1 commit + env |
| W7 | 收口 + 无件项 | 全量回归 `failed` 不增 | 1 commit |

关键前置裁决：**Q1** 未合并分支 `feat/toolplane-execution` 先合流还是先冻结（影响 W4~W6）；
**Q2** 装配内核接线点（mca 零冲突 vs TUI 主路径）；
**Q3** 是否接受"写并发后审计序降级为按资源保序"。
