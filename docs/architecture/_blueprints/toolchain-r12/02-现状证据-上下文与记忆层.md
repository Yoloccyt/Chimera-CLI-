### A.4 压缩器评分公式与 Top-K 算法复杂度

**【事实】评分公式（四维，w4 来源维度默认开启）：**
```
score = w1·(1-sw)·recency + w2·(1-sw)·frequency + w3·(1-sw)·relevance + sw·src_factor
sw = config.source_weight（默认 0.10）
recency = 1 - min(Δt/time_span, 1)；frequency = access_count/max_access_count
relevance = task_clv·entry_clv 余弦 clamp[0,1]，无 CLV 取 0.5
src_factor 经 assemble::source_value_factor 单点表，None 条目取 0.5
```
证据：`crates/hcw-window/src/compressor.rs:87-134`；权重默认 `(0.4,0.3,0.3)` `crates/hcw-window/src/config.rs:200`；`source_weight` 默认 `0.10` `crates/hcw-window/src/config.rs:202`；合法域 `[0.0,0.5)` `crates/hcw-window/src/config.rs:145-152`。

**【事实】Top-K 复杂度 = `O(n + K·log K)`，非全排序：**
- 评分：`O(n)`，若走并行则按 `CHUNK=64` 分段（`crates/hcw-window/src/parallel.rs:53`、`:177-230`）。
- K 上界估计：`estimated_k = (effective_target / min_token_size).min(n).max(1)`，`crates/hcw-window/src/compressor.rs:303-309`。
- `select_nth_unstable_by(estimated_k-1)` → `O(n)`；仅 Top-K 段 `sort_by` → `O(K log K)`；随后 `truncate(estimated_k)`，`crates/hcw-window/src/compressor.rs:311-328`。
- 语义折叠循环：对 Top-K 逐条与"已保留代表表"比余弦，最坏 `O(K·R·512)`（R = 代表数），`crates/hcw-window/src/compressor.rs:348-362`。【推断】该循环是 K 的二次量级，但 K 受预算约束（通常 ≤ 数百），实测未见尖峰。

**【事实】评分阶段的并行注入点**：`bridge().route(TaskKind::HcwEntryScore, n)`，阈值 200（注释），`Inline` 则串行，`crates/hcw-window/src/parallel.rs:104-116`；env 逃生 `CHIMERA_NO_PARALLEL_HCW`，`:47-72`。
