# ADR-265: RSS 峰值采样口径（R5 工单 B）

- **状态**：Accepted（2026-11-08，工程工单 Tranche 1；dev-only 参考证据面）
- **上游**：工程工单「阶段 2 工单 B」；ADR-263 §3（明文承认「内存峰值未测」缺口的补测）；ADR-264（代理指标硬验收定位不变）
- **关联**：ADR-263（分配预算棘轮=分配次数面）/ ADR-264（本工具仍属参考旁证）

## 1. 背景

任务书把「RSS 峰值」列为 CPU/内存维度的显式诉求；核验（工程工单阶段 0）
确认现测体系仅有 WorkingSet64 **单点快照**（无峰值），`PeakWorkingSet64`
全仓 0 命中。ADR-263 的 CountingAlloc 只计分配**次数**（非字节水位），
RSS 峰值是真实测量缺口。

## 2. 决策

**D1 · 双口径并列，防单口径误读**（`scripts/energy_profile.ps1`）：

- **窗口峰值** = 采样环内 `WorkingSet64` 最大值（粒度 `$PollMs` 默认
  500ms，可调）——回答「本次测量窗内进程吃到了多少物理内存」；
- **进程生存期峰值** = `.NET Process.PeakWorkingSet64`（OS 自进程启动的
  记账峰值，含启动段）——回答「该进程历史最高水位」。
  两者并列输出（窗口峰值 ≥ 窗口均值恒成立；生存期峰值 ≥ 窗口峰值，
  差值 = 启动段或其他时段贡献）。

**D2 · 单环采样**：CPU%（IntervalSec 粒度）与工作集轮询（PollMs 粒度）在
**同一时间环**内采集——能耗旁证要求 CPU% 与 RSS 峰值可同帧引用，分离两环
会失去「同一测量窗口」语义。

**D3 · 口径边界（诚实登记）**：WorkingSet ≈ **物理驻留**字节，非提交内存
（commit charge）——RSS 峰值不等于进程对页面文件的占用量；任务管理器
「内存（活动专用工作集）」与本口径同族。跨进程对比时必须同口径。

**D4 · 定位不变**：dev-only 参考旁证（不入 CI 门禁）；硬验收仍是代理指标
（分配数/CPU-ms/空闲唤醒率，ADR-264 §2）。RSS 峰值补的是「运行期水位」
证据面，供内存回归排查与容量规划引用。

## 3. 验证

2026-11-08 实测（explorer 多实例进程，6s 窗口 / 300ms 粒度）：窗口峰值
148.1 MB ≥ 窗口均值 148.1 MB，生存期峰值 402.9 MB 独立呈现，CPU% 同环
采样正常——双口径与单环设计全部按 §2 工作。G-85（PS1 BOM 门）28/28 保持。

## 4. 回滚

单文件 revert（脚本为纯增量工具，无下游消费方）。
