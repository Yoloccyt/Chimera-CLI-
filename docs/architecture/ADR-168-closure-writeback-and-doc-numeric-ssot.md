## 问题（仅保留可核实部分）

一条已被后续 ADR **关闭**的指标偏差，仍在上游登记表里以"⚠️ 待办 + 缓冲消耗"的**未关闭形态**存在，并被下游文档当作当前状态引用：

| 位置 | 现状（2026-08-31 逐字核实） | 应有的现状 |
|---|---|---|
| `docs/reports/phase4-wave4-closure.md:58` | `55.2%（-9.8pp） \| ⚠️ ADR-155 登记 + RK-P23 缓冲消耗 1 次` ——**无"已关闭"指针** | 同一行应指向 ADR-157 的关闭结论与实测值 |
| `docs/governance/RK-P_risk_register.md` RK-P23 | 已正确标注 `✅ 已关闭（ADR-157 双口径三条件，combined 0.552→0.999）` | 已正确（本 ADR 不重复处置） |
| `ADR-153-156-phase4-governance.md` ADR-155 行 | `按需 \| W23（P4-T8，如触发）` | 需补"已被 ADR-157 取代判定口径" |

即：**关闭动作只写进了风险登记册与 ADR-157，没有回写到"最初记录该数字的报告"**。任何从 `phase4-wave4-closure.md` 读到 55.2% 的人，都会拿到一个已被推翻的前态，而且**没有任何检查会因此变红**。

这与本波次反复出现的"写了不跑 / 登记不偿还"病灶同族（RK-P30），区别是方向：这次不是门没跑，而是**结论文档没跟着状态走**。

## 决策

1. **关闭必须回写到"数字第一次出现的地方"**：任何被下游引用的偏差/告警/阈值，在其状态变为已关闭时，须在**原始记录行**追加 `→ 已关闭（<ADR 编号>，<实测值>）`，不得只在登记册单方面标注。判定标准：从原始行出发一跳即可读到关闭结论。
2. **文档数值 SSOT = `scripts/perf_thresholds.toml`**（与 `slo.yml` / `bench_check.yml` 同源）。文档引用阈值时写"值 + 到该 toml 的键路径"，不写裸数字；裸数字没有可核对的真值来源。
3. **给文档一致性巡检加一条"关闭回写"检查**（D7 候选）：对登记表中标为"已关闭"的每一项，若其**来源文件与行号**存在且该行不含"已关闭"或其 ADR 编号 → FAIL。行号定位用 `文件:行` 直读，找不到即判"不可判定"并退非 0（**不接受静默跳过**——本仓库已因"缺文件即崩"与"缺文件即跳过"两种极端各吃过一次亏）。
4. **不新增 `rust-toolchain.toml`、不改 `.gitignore` 的 `*.md` 策略**（红线）；本 ADR 的检查全部落在本地权威执行体（`.ps1` / `py`），与 ADR-166 的执行面重划一致。
5. 浮点比较一律用绝对误差界，禁 `format!("{:.2}")` 字符串比较（会把 `0.3004` 判成 `0.30`，放过漂移）。

## 后果

* 正向：偏差从"登记了但读者看不到它已关闭"变成一跳可达；`phase4-wave4-closure.md:58` 这类"前态快照"不再静默误导。
* 正向：检查 3 是**可机械判定**的，不依赖人记得去回写。
* 负向：需要给已发布的 closure 报告补行内标注（会改动历史报告的表格行）。缓解：只追加不改写原判定文字，并在报告首部注明"本行为 2026-08-31 关闭回写"。
* 负向：D7 需要一张"已关闭项 → 来源行"的映射表，存量需人工梳理。缓解：先只做 RK-P 主册（机器可读的"来源"列已有该格式，如 `phase4-wave4-closure.md:58,73`）。
