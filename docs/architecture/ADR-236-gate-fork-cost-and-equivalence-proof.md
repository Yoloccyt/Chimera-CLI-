# ADR-236：治理门的 fork 成本与"改实现不削判据"的等价性判据（工具链第六波）

- **状态**：已接受（2026-11-05）
- **范围**：本仓一切"治理门 / CI 脚本"的**性能与调度成本**改造——判据语义不变，只改实现形状；不是新增能力（那在 ADR-233/235）
- **相关**：`ADR-234`（性能/并行判据层；本 ADR 是它在**工具链侧**的同构应用）、`ADR-233` 追加节九/十（慢门耗时登记）、`ADR-228`（govd 调度器）、`scripts/gate_manifest.toml`
- **本波落地的三条**：G-07 `audit_commit_coupling.py`、G-08 `check_dependency_rules.sh`、G-36/G-37 `check_doc_drift.sh`；另含 S4 的墙钟 flake 消除（`mcp-mesh` 2PC 重试用例）

---

## 1. 背景：本仓最贵的三条门，成本单位是"进程"而不是"工作量"

第四波收口时登记过三条慢门的耗时（G-07 107.3s / G-08 157–223s / G-36 `--selftest` 82.6s，
而它真跑仅 13.6s）。本波第一次量到**为什么**慢。在目标宿主（Windows 11 + Git Bash，
15 GB 机型）实测两个单价：

| 构造 | 单价 | 测法 |
|---|---|---|
| `$(...)` 命令替换，即使内部只是内置 `case` | **74.01 ms** | 1000 次 `v="$(f a)"`，f 是纯 case 函数 |
| 外部命令（`basename`） | **117.87 ms** | 1000 次 `v="$(basename /tmp/xyz)"` |

⇒ 一条 `tr | sed | grep | grep | sed` 五段流水线 ≈ 0.6 s；而旧实现**每个 crate 跑一条**、
`$(layer_of …)` **每个依赖跑一次**、`$(printf | grep | head)` **每条命中跑一次**。
三条门的耗时与树的大小基本无关（G-36 的自测在 12 个文件的合成树上要 58s，
真树 46 crate 只要 9.8s）——因为成本全是 fork。

探针实测（G-07，桩掉 `subprocess.run` / `os.walk` 后只数调用次数，给出上下界两模式）：

```
mode=none-tracked  子进程 2928  os.walk 6362 次 / 累计 2,622,586 个文件条目
mode=all-tracked   子进程  732  os.walk 6362 次
```

⇒ 结论：**主因常常不是"调了 git"，而是"每个引用重走一遍目录树"**。这条只有在
把调用次数打出来之后才看得见；读代码时我第一版判断"是 N+1 个 git spawn"是错的。

---

## 2. 决策

### D1 — 治理门的一等成本单位是"子进程数"，改造顺序按"调用次数 × 单价"排

任何门脚本改造前先量三件事，并把数字留在提交信息里：① 外部命令/子 shell 调用次数
（用桩计数器，两种极端返回值给上下界）；② 目录遍历次数与累计条目数；③ 本机两个
单价。缺任何一项就动脚本，等于在没测过的前提下改运维参数。

### D2 — 改判据实现必须做**新旧逐字节对拍**，且真树全绿时**必须另建红态夹具**

只跑一次新版"没红"不构成证据：干净真树上 G-07 输出 0 条、G-36 输出 `[OK]` 一行，
两版都为空 ⇒ 对拍没有信息量。所以本波每条门的等价性证明都是两段式：

1. **红态合成夹具**：造一个目录树/仓库，把每类判定各植入至少一条
   （G-07：`REF_UNTRACKED`（已在 HEAD / 本次新入两种 tag）、`BOTH_UNTRACKED`、
   `IGNORED_TARGET`、被跟踪⇒无约束、裸名经 `docs/` 解析；
   G-08：GAP-B×2、GAP-E、GAP-C 未声明依赖、GAP-C 磁盘未登记、GAP-D 17>16，
   外加 CRLF manifest、`[dependencies]` 非首节、`[dev-dependencies]` 里的
   `workspace = true`（必须排除）、`pvl-layer={workspace = true}` 无空格写法、
   裸版本号引用、根 manifest BOM；
   G-36：直接复用它自带的 6 例 `--selftest`——未登记漂移/已登记漂移/陈旧登记/
   代码漂移/`--update-baseline` 再锁/缺目标退 2，即红态与绿态都覆盖）；
2. **同一夹具 + 同一真树，新旧两版各跑一遍，`diff` 必须为空**，且退出码相同。

本波这条判据立刻产生了价值：它抓出三个只有新版才会犯的错误（见 §3）。

### D3 — 消除 fork 的三种手法，按"单一真值源不被复制"排序

| 手法 | 用在哪 | 为什么安全 |
|---|---|---|
| **批量集合视图**：把逐项 `git ls-files --error-unmatch` 换成一次 `git ls-files` + 集合判定；`cat-file -e HEAD:p` 换成一次 `ls-tree -r --name-only HEAD`；逐项 `check-ignore` 换成一次 `--stdin -v --non-matching` | G-07（2928 → 3 次子进程） | 三个视图与逐项判定的语义逐条对齐，并为此必须 `-c core.quotePath=false`（否则非 ASCII 路径被转义，"已跟踪"会被判成"未跟踪"） |
| **一趟遍历建图/建索引**：basename→路径索引、`crate<TAB>dep` 依赖图，各由一次遍历/一次 awk 产出，check 侧只查数组 | G-07 的 `os.walk`（6362 → 5）、G-08 的 manifest 解析 | 遍历顺序与剪枝规则**照抄**旧实现（G-07 只剪 `target`、G-08 只取 `[dependencies]` 到下一个 `[` 之间），改动顺序或剪枝集合都会改判定面 |
| **惰性记忆化包装**：被解析的函数本体一字不动，外面套一层 memo 写全局变量 | G-08 的 `layer_of`（46 个 crate × 多轮 → 每个**不同名字**一次） | `layer_of()`/`sublayer_of()` 的 `case` 表是 `check_l0_sublayer.py`(G-125/126) 的**解析对象**；各 Check 块的比较行、`continue` 行数、`[GAP-x]` 发射点数是 `check_gate_predicates_parity.py`(G-38/39) 的解析对象 ⇒ 只能"套壳"，不能改形 |

### D4 — 时间相关的测试判据一律用虚拟时钟，并配一条"预算容不下"的正控

`#[tokio::test(start_paused = true)]` 让 `tokio::time::sleep`/`timeout` 走虚拟时间。
本波用它换掉了 mcp-mesh 2PC 重试用例的墙钟依赖（96% 内存压力下失败过一次）。
**只切时钟不够**：只有"预算内成功"这一半时，把 timeout 调大或把退避调小都能继续绿。
于是新增配对用例：`transaction_timeout_ms = 10` < 首次退避 50ms ⇒ 必须
`Err(TransactionTimeout)`，这条把"超时机制真在生效"变成仓内可机检事实。
采纳范围仅限 dev-dependencies（`test-util` 特征），且与 mas-sched / nexus-hook /
chimera-mas 三处既有写法一致。

### D5 — 自造对拍夹具的三条纪律

1. **被测脚本的两版副本要放在它自己的扫描面之外**（本波放 `tools/`）：否则
   "old_g07.py / new_g07.py" 会作为 holder 被扫进去，holder 名差异成为输出的唯一差异，
   对拍立刻失去意义；
2. **退出码不许写进被对拍的文件**：本波第一版把 `OLD_RC=` / `NEW_RC=` 追加到输出尾部，
   于是 diff 必然非空——差异是我自己的标注而不是判定结果；
3. **夹具自身要可重入**：Windows 上残留句柄让 `rm -rf` 报 `Device or resource busy`，
   因此目录名要带序号回退，不能假设"清空后重跑"。

### D6 — 登记为棘轮的读数：三条门的改前/改后耗时同印

| 门 | 改前（本机现取） | 改后 | 输出对拍 |
|---|---|---|---|
| G-07 `audit_commit_coupling.py` | 102.19s / 102.46s | **1.61s**（63×） | 真树 + 红态夹具均 BYTE-IDENTICAL |
| G-08 `check_dependency_rules.sh` | 161.76s（串行基线）/ 201.36s（复测） | **7.83s**（21–26×） | 同上 |
| G-36 `check_doc_drift.sh --selftest` | 58.13s | **8.11s**（7.2×） | 同上 |
| G-37 `check_doc_drift.sh`（真跑） | 9.77s | **2.53s**（3.9×） | 同上 |

> G-08 两个改前读数相差 25%，是宿主负载造成的真实抖动——**同印两个数**而不是挑一个
> 好看的，是 ADR-234"冷启动首轮高 29–33%"同一测量学事实在工具链侧的翻版。

## 3. 本波被自己的对拍/夹具抓出的三个缺陷（都不在"被测工件"里，而在仪器）

| # | 缺陷 | 危害方向 | 抓出它的是 |
|---|---|---|---|
| 1 | `subprocess.run(..., text=True)` 会把 stdin 的 `\n` 按宿主行尾翻成 `\r\n` ⇒ `git check-ignore --stdin` **一个都不命中** | **假红**（`IGNORED_TARGET` 被升格成硬耦合） | 红态夹具的新旧对拍 |
| 2 | glob 与 regex 的 `*` 语义不同：把 sed 的 `[[:space:]]*\|[[:space:]]*` 直译成 bash pattern `[[:space:]]*\|` ⇒ `*` 变成"任意字符"，登记行被吞成 `docs/...md\|` | **假红 + 漏判**（drift 登记失效 ⇒ 本该 WARN 的变 FAIL） | `--selftest` 第 3 例（已登记漂移必须 WARN 且 rc=0） |
| 3 | 首版 `${LAYER_OF_MEMO[$dep]-}` 直读 memo 数组，把"未查询过"当成"无层号" | **假红**（selftest 模式下 46 个层表名会全报"无 layer"） | selftest 与真跑的 rc 差异（复跑即红） |

三条同族：**批量/新语言写法替换逐项调用时，等价性不在"看得像"，而在被两侧各测一次**。
第 2 条与本仓已登记的 `gsub/tr 是字符集合不是子串` 同一课。

## 4. 证明力上限

1. **耗时是本机单点读数**：CI runner（ubuntu-latest）上 fork 单价远低，收益幅度不可外推；
   本 ADR 只主张"调用次数从 N×M 降到常数"这一结构性事实。
2. **CI 侧未跑**：三条门的 CI 步骤（`ci.yml` 里的 G-07/G-08 阻塞步、bench_check 的 I10/I11）
   首跑才是最终判决；本波未改任何 workflow 文件。
3. **G-07 的 `--selftest` 未入门清单**：新增 manifest 行按"四件同批"纪律要同批接 CI 步，
   而 workflow 改动需另行授权；本轮以本地实跑 + 红态夹具对拍为证据，并在此登记为待办。
4. **重跑门数不变**：门总数/普查常量未动（本波不增门、不改 `test_kind`/`kind`），
   因此 `test_govd` 的普查断言不受影响（复跑见报告）。
