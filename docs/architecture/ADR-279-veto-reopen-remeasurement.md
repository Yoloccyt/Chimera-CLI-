# ADR-279 -- 四项既有否决的复评：按各自自述重开条件裁决（全部维持）

- 状态：Accepted（2026-11-10）
- 决策者：W1 波次
- 关联：ADR-249（借用脊柱）/ ADR-263（mimalloc）/ ADR-275（装配期并行）/ ADR-277（PlanRunner 固定开销）/ ADR-260（seccore 判决体，R1）
- 影响面：仅 ADR 与证据日志；**零生产代码**
- 行为影响：无（四项均维持原否决；不新增 feature、不切默认分配器、不改组合根）

## 1. 方法：只在「自述重开条件」满足时复评

本波不是「无条件重做否决项」，而是逐条读各 ADR 的**自述重开条件**，只对满足条件的项重跑原始判据：

| 项 | 自述重开条件 | 现势 | 动作 |
|---|---|---|---|
| ADR-249 | 「出现 ≥1 个高频借用路径生产调用方，**或 seccore 判决体优化（ADR-260，R1）落地后分配占比显著上移使 2 次分配节省跨过 5% 门**」 | ADR-260 **已落地**（`3dbcf608`） | **重跑原始 bench** |
| ADR-263 | 「① R1/R2 后分配占比重新成为主导（**分派发预算棘轮读数显著上升**）；② 出现高频大分配载荷」 | 分配棘轮测试仍通过（预算 7 次/派发，未上升）；无新大分配载荷 | **不重跑**（触发读数未变） |
| ADR-275 | 「分段实测显示**四段合计 ≥5ms 且单段 ≥2ms**，否则不再重提」 | `composition_build_auto` 453.87µs | **一次确认测量 → 维持** |
| ADR-277 | 无重开条款；前提 `MAX_STEPS=64` 未变 | `--plan-max-steps` 为 min 语义（只收紧） | **维持，不重提** |

## 2. ADR-249 借用脊柱：重跑后否决更强（方向反转）

命令：`cargo bench -p gqep-executor --bench dispatch_borrowed_chain -- --noplot`（sample_size 30）

| 测点对 | owned median（95% CI） | borrowed median（95% CI） | 比值（borrowed/owned） | CI 关系 | 判定 |
|---|---|---|---|---|---|
| c1 | 187.33 µs [186.59, 188.15] | 193.67 µs [192.00, 195.88] | **1.034** | 不相交（borrowed **更慢**） | ✗ |
| c4 | 185.80 µs [184.64, 187.17] | 193.31 µs [191.26, 195.85] | **1.040** | 不相交（borrowed **更慢**） | ✗ |
| c8 | 190.13 µs [189.32, 190.91] | 189.23 µs [188.15, 190.64] | 0.995 | 重叠 | ✗ |

**裁决：维持否决（ADR-249 D1 不变）。**

对照原 ADR-249 的 0.971 / 0.998 / 0.998：
- 绝对耗时从 ~403µs 降到 ~187µs（−54%），佐证 R1 判决体优化确实落地；
- 但比值没有向 ≤0.95 靠拢，c1/c4 **反而翻成 borrowed 更慢**。
  ⇒ 触发条件的前提（「2 次分配节省会因占比上移而跨过 5% 门」）被实测否证：
  分配不是瓶颈，borrowed 的间接层成本比它省下的 2 次分配更贵。
- 不进入 W1b（不重新实施 8 文件脊柱改造）。

## 3. ADR-263 mimalloc：触发读数未上升，不重跑

ADR-263 的重开条件①把「分配占比重新成为主导」操作化为「分派发预算棘轮读数显著上升」。
现跑 `cargo test -p gqep-executor --test dispatch_alloc_budget`：**1 passed**（预算 7 次/派发未被突破）。
读数没有上升 ⇒ 触发条件不满足，**不重跑六测点 A/B**，维持「不设默认分配器」。

**何时该重开**：预算棘轮被合法上调（新功能确实需要更多分配），或出现新的大批量分配载荷。
届时用原判据（median ≥5% **且** 内存峰值不升）重跑，而不是「方向为正就采纳」。

## 4. ADR-275 装配期并行：确认远低于重开门槛

命令：`cargo bench -p chimera-cli --bench composition_root_bench -- --noplot --quick`

| 组 | median |
|---|---|
| `composition_build_off` | 59.478 µs |
| `composition_build_auto` | **453.87 µs** |
| `composition_build_app_server` | 2.0646 ms |
| `composition_handle_op_turn_submit` | 1.9828 ms |

ADR-275 的门槛是「四段合计 ≥5ms 且单段 ≥2ms」。`build_auto` 整条装配 453.87µs，
远低于 5ms；四个分段更小。**维持否决**（装配期串行不构成瓶颈）。
`build_app_server` 的 2.06ms 是另一宿主（app-server）的完整构建，不是 ADR-275 的四段口径，
不用于改判。

## 5. ADR-277 PlanRunner 固定开销：前提未变，防重提生效

`--plan-max-steps`（ADR-269）在 `PlanGuards` 上是 `min` 语义（只收紧、不放宽），
故 `MAX_STEPS = 64` 的硬上界未变；四项固定开销仍是 µs 级。**维持，不重跑**。

## 6. 未采纳

| 项 | 理由 |
|---|---|
| 因「复评」而无条件重做借用脊柱 | 实测三对全不达标且两对更慢；重做是负收益 |
| 因「方向为正」就切 mimalloc 默认 | 原判据要求 median ≥5% 且峰值不升；方向证据 ≠ 过门 |
| 为 ADR-275/277 重跑并改判 | 门槛/前提未变；重跑只会制造噪声与治理争议 |
| 把本 ADR 写成「翻案记录」 | 四项均为**维持**；本 ADR 的价值是证明「否决项有可证伪的重开机制」 |

## 7. 证据边界

- 全部为**同机同 HEAD** 的 criterion 读数；跨轮 `change` 不可归因（ADR-267 教训）。
- ADR-263 未重跑是**判据驱动**的（触发读数未上升），不是省略；若未来读数上升，须按原判据重跑。
- ADR-249 的 c1/c4 绝对值与 ADR-275 的分段数受本机 Windows GNU 与后台负载影响；
  比值与门槛判定在同轮内自洽。
