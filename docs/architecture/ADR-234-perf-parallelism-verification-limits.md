# ADR-234：性能/并行化工作的验证判据与证明力上限（工具链第四波的判据层决策）

- **状态**：已接受（2026-11-03）
- **范围**：本仓一切"性能优化 / 并行化重构"波次的**验收判据**——不是某次实施决策（那在 `ADR-233` 追加节九）
- **相关**：`ADR-233`（工具链执行面决策日志）、`ADR-232`（LLM 工具循环与审批分档）、`ADR-228`（govd 治理调度器）、
 `agents.md §3.4.1 原则 6「性能可证伪」`、`§6.1「结果不许丢」`、`§6.2「禁止持锁 .await」`

---

## 1. 背景：为什么需要这份 ADR

第三波收口时，本仓连续出现**四类"看起来已验证、其实没有"**的读数。它们不是同一错误的四次重复，而是四种
不同的失效机制，各自需要一条明示的判据才不会再犯：

| # | 机制 | 本波实锤（命令现取） |
|---|---|---|
| 1 | **探针看不见被检物**，两侧读数相等被当成"无退化" | `tui_update_cost_bench.rs` 驱动 `app.update()`，而 `poll_approvals()` 在 `step()` 里；两条路径不相交 ⇒ 该 bench 对弹窗通道**构造性盲**。控制组 `llm_diag_request_rebuild` 量请求体复用，拿它当弹窗成本对照是范畴错误 |
| 2 | **用不可分解的量证需要分解的命题** | `BoundedToolScheduler` 的 `SchedSnapshot::peak_in_flight` 是**两车道合并**的高水位（`scheduler.rs:25-26`），且 LLM 路径的 `ToolPriority::Normal` 与 `Background` 同车道（`:90-95`）⇒ 它无法区分"车道被谁占" |
| 3 | **判据两侧都失败被当成不对称** | 终验投影分类原用 `git ls-files --error-unmatch` 区分"只有一侧有"。实测九个被点名文件**两侧都失败**（`.gitignore` 的 `*.md`、`.trae/`）⇒ 测不出不对称，会把投影限制误判成真债（`ADR-233` D32 已就地改为两侧 `test -f`） |
| 4 | **环境不足被读成"没跑出问题"** | 现取 `D: free=9.9GiB`，而 7 道 heavy 门里 **6 道要求 `disk_gb=20/25`** ⇒ `--with-heavy` 也只得 `UNKNOWN`。"本地全门无红"在此环境下是**不可判**，不是通过 |

另有一条测量学事实贯穿全部：同一棵树连跑 4 轮 criterion（`--profile bench-lite --sample-size 10`），
组内中位数带宽 `/1` 4.5%、`/64` 2.1%、`/256` 8.0%，而**冷启动首轮比后三轮高 29–33%**。
⇒ 任何小于冷启动量级的差值都不构成回归或改进的证据。

## 2. 决策

### A1 — 性能/并行化结论按四层判据取用，优先级固定

| 层 | 判据 | 能证 | 不能证 |
|---|---|---|---|
| **L1 结构判据**（首选） | ①上界成立：`peak_in_flight ≤ 窗口`；②**完成序/区间重叠**：∃ i≠j，`start_i < finish_j ∧ start_j < finish_i`；③阳性对照：把被测性质改坏，用例必须红 | "并行在结构上成立"、"屏障确实消失"、"上界未被击穿" | 快了多少 |
| **L2 运行时计数器** | `SchedSnapshot`（`waiters`/`background_in_flight`/`peak_in_flight`）、`shard_depths()`、`backpressure_stats()`、`pool_active_tasks()`、`hottest_kind()` | 方向性不等式（"从 1 抬到 ≥2"）；挤占是否存在 | 毫秒级收益、绝对延迟 |
| **L3 比值型墙钟**（仅限调度器自身） | govd：`sum(attempt.duration_s) / (run_end.ts − run_start.ts)`；改前实测 **0.986**（137 attempt、559.3s / 567.1s） | 串行↔并发的**结构性**变化 | 产品路径延迟 |
| **L4 criterion 阈值**（终判） | `perf_thresholds.toml` + `bench_check.yml` 的 CI 首跑校准 | "无 ns 级回退"、收益幅度 | 本地一次读数不能定阈值 |

**判据缺失时**的合法动作只有两个：把该结论登记为**未验**，或先补判据再宣称。**不许**用 L2/L3 冒充 L4，
也**不许**用"测试全绿"顶替 L1（测试绿只证明语义未削，与性能无关）。

### A2 — 明令禁止的四种证明方式

1. 用 `peak_in_flight`（合并高水位）证"某一条车道没被钉住"——量不可分解。改用完成序，或先给快照加分解维度（那本身是一项改动）。
2. 用 `bench X 前后读数相等`证"改动 Y 无成本"，当且仅当 X 的驱动路径不含 Y——必须**先证 X 能看见 Y**（做法：对 X 施加一次已知会动的变异，读数必须动）。
3. 用两侧都失败的命令做不对称判据（`git ls-files` 之于被忽略文件）。不对称必须由**两侧语义不同**的探针给出（`test -f`）。
4. 用 flaky 计时断言（"总墙钟变短了"）当用例断言。用例只断言**形状**（上界、存在性、顺序），墙钟只进报告不进断言。

### A3 — 证明力上限的合法句式（原话模板）

> 「L1 结构判据成立（用例名 + 反证红因）＋ L2 方向性成立；**绝对阈值待 CI 首跑校准**，本地不锁。
> 全量 heavy 门在本宿主为 `UNKNOWN`（磁盘现取 X GiB < 要求 Y GiB），故不宣称"全门绿"。」

任何省略后半段的表述都视为过度声明。低报同样算错：不得把可行的中间选项一并报成"只能等 CI"。

### A4 — 环境不足的处置（本波定，后续沿用）

- **不**为让门"能判"而调小 `disk_gb`（那是削减门强度）。
- **不**擅自 `rm -rf target/`（破坏 criterion 基线；清理时机属用户）。可提议，不动手。
- **不**擅自改 `.github/workflows`（本机权限面亦拦截）。需要 CI 侧接线时，**贴出待加片段征求确认**；未获授权的批次不得声称受 CI 守护，并须写明"门在清单里、CI 不跑"这个中间态的风险（`ADR-233` 记过反向半接线态判红的先例）。
- 覆盖率与 fuzz：Windows-GNU 宿主实测 `error[E0463] can't find crate for 'profiler_builtins'`、libFuzzer 仅适配 MSVC ⇒ 归 CI，本地只承诺测试面（用例 + proptest 属性）。

### A5 — 反事实与自证的最低标准

- 每条"某判据有牙齿"的主张必须附**一次真实的红**（植入坏例或翻转极性），且红因与预期一致（打印实际观察值，不接受"rc≠0 即算红"）。
- 变异跑完的复原必须 `sha256sum -c` **逐字节自证**；不等即中止，绝不带着半个变异体提交。
 （本仓实锤过：`shutil.copy2` 保留 mtime ⇒ cargo 复用**变异体二进制**，"复原后仍红"是缓存假象。）
- **测量态与提交态必须同一棵树**：全量门跑动期间不改任何被检文件；派生面（契约头、`docs/architecture/views/`）
  与台账行必须和被检物**同批**落地（`ADR-233` 追加节八记过"只刷一个派生面"的漏刷）。
- **自造分类器/探针必须先被允许拒绝出结论**：任一被测对象未能真正执行 ⇒ `[PROBE-ERROR]` + 退 2、不出分类；
  解析条数低于地板 ⇒ 判为致盲并退 2。致盲的读数长成结论是最贵的一类错误。

---

## 3. 后果

1. 本波（`ADR-233` 追加节九 S 系列）每条性能结论都按 A3 句式落报告，未达 L4 的一律写"待 CI 校准"。
2. L1 判据优先带来一个副作用：**并行化改动必须先能构造"完成序可观测"的测试夹具**（sleep + 时间戳记录），
  这比"跑一遍看快没快"贵，但它不受宿主噪声影响，是本仓唯一可跨机复现的形状。
3. A2-2（"先证探针能看见被检物"）会周期性否决既有 bench 作为验收手段——这是有意的：
  本仓已三次靠"报告型/结构性盲区探针"给出过看似结论的读数。
4. A4 使"本地全门绿"在这台机器上**永不成立**，因此发布判定必须把 CI 记账（或主检出全量）纳入，而非本地一次跑。

## 4. 被否决项

- **R-A 用"测试全绿 + 人工 review"替代 criterion**：否。`§3.4.1` 原则 6 要求性能可证伪；且本波实测同码噪声带宽已达 8–33%，绿测与性能无关。
- **R-B 临时改 `release`/`bench-lite` profile 以省时间**：否。`lto/codegen-units/opt-level` 会污染阈值测量、制造假失败（`ADR-225` 已登记）。
- **R-C 为让 `peak_in_flight` 可用而顺手给快照加分车道字段**：本波不做（属独立契约变更，且会牵动 `SchedSnapshot` 消费方）；若将来要做，须另立决策并在同一批把 A2-1 的禁令解除。
- **R-D 降低 heavy 门的 `disk_gb` 到 10**：否，等同 R-A 的另一种写法——把测不到写成测过了。
