> `docs/reports/v3.5-baseline-measurement-2026-xx-xx.md`」，但该**具名交付物在本批前 19 轮里从未落盘**——

## 1. M1 — 六条 SLO 复现（G-A 判据前置）

- **判据**：`check_perf_redlines.py slo` 六条 SLO 全 PASS，且余量可报告。
- **读数**：**全 PASS，最小余量 5.8×**（A 级）。
- **命令**：`py -3 scripts/check_perf_redlines.py slo`；静态侧 `py -3 scripts/check_perf_redlines.py --static-only` rc=0。
- **用途**：为冻结项裁决包的 G-A（“性能无判红”）提供实跑支撑，替代此前只有转述的证据链。
- **未闭合面**：本项只在**本机**跑过；跨机一致性仍属 clean-runner 待办（§8）。

## 2. M2 — `hot_lru` / `hnsw_tiered` 三档对照

- **判据**（Spec 原文）：空闲/高压中位数比 > 1.5 即认定读数被内存压力污染；同 commit 双档差 > 10%
  即认定构建/页缓存噪声。
- **已做档**：本机**同进程双序复测**（`cargo bench -p cmt-tiering --bench hot_lru` /
  `cargo bench -p mlc-engine --bench hnsw_tiered`，均 `--test-threads=1`）——W5-C 报告的
  `hot_lru` 2.8× / `hnsw_tiered` 2.9× 选择性退化 **未复现**（A 级）。
- **结论修正**：既然同规模双序复测不重复该退化，「本机内存压力致因」由“已证”**降级为未证实**；
  不得继续拿它当“本机读数被污染”的解释（解释力丢失，不等于污染不存在）。
- **未做档（直写）**：本机**高压复现档**与 **CI clean-runner 档**未做 ⇒ Spec 要求的「三档对照」
  实际只完成两档的一部分。`hnsw_tiered` 因此**维持 B 级**（`target/criterion` 无该组目录，
  `tmp/w5-slo-benches.txt` 不在盘）。

## 3. M3 — `ClvSimilarity` 拐点重定（P-2 前置）

- **判据**：256/384/512 各 ≥5 轮**交替随机序**；每点 ≥4/5 轮 median 同号才算拐点存在。
- **实施**：`crates/chimera-cli/benches/overwindow_bridge.rs` 新增 384 点位 + `_rev` 反序对照组；
  轮次与同号检验由 `tmp/m3_knee_rounds.py` 承担（盘上仍在）。
- **读数**：**n\* ≤ 256**，六点全 5/5 同号且换序不翻转（A 级）；对照盘上
  `target/criterion/overwindow_dense_knee/*/base/estimates.json`：n=256 时 offload 已快 **1.295×**
  ——与旧报告给出「287 且此处慢 10%」的符号**相反** ⇒ 旧拐点值不可复现（Spec Key Change 2 已入账）。
- **裁决影响**：P-2 决策包的落差下界改述为「n\* 目前不可辨识（≤256 或落噪声带），生产带明确在右侧」；
  阈值 **维持 1000**，真改走法 B（`update_threshold` + `measured_at` 非 0），需 clean-runner 重标定 + ADR。

## 4. M4 — `r2_unfreeze` 轨可编译与实跑

- **命令**：`cargo test -p chimera-cli --features r2_unfreeze --lib`。
- **读数**：**197 passed / 0 failed**（A 级）。
- **口径边界**：前科属实但**位量不同**——“r2_unfreeze 分支从未编译通过”写在
  `crates/chimera-cli/src/composition.rs:191`（“引擎未实现 Default（仅 new(GsoeConfig)），
  此前写法使 r2_unfreeze 分支从未编译通过”）；feature 定义在 `crates/chimera-cli/Cargo.toml:19`，
  默认 off 的理由在 `:85`，e2e 入口在根 `Cargo.toml:390-391`（`r2_unfreeze_path_e2e`）。
  本次证明的是 **可编译 + 测试绿**，**不等于 R2 行为已验证**；CI 仍不启用该 feature（ADR-195 D7 / R-1 缓解）。
- **对 Spec 引文的一条否证**：W6-1 M4 括注写“`Cargo.toml:191` 注释已有‘从未编译通过’前科”——
  **行号对、文件错**（实为 `composition.rs:191`）。本汇总不沿用该错引用；根 `Cargo.toml:191` 实际是
  virtual manifest 的注释，与 r2 无关。
- **裁决影响**：F-3（RL/Python/R2 维持冻结）新增“可编译”这条正面证据，但解冻判据仍要
  ADR-042 五条件 + ADR-053 rev4 批次判定 + ADR-054 签署，未因此松动。

## 5. M5 — G-86 加速器排除门的 tract 盲区夹具

- **判据**：向 scratch lockfile 注入 `tract-onnx` 与 `wgpu` 各一条，看扫描是否命中。
- **读数**：负向夹具 **8/8 通过**（A 级）；`wgpu` / `ort` / `candle` 拦住，
  **`tract-onnx` / `tract-linalg` 不拦**（它们不在 `EXACT_FORBIDDEN`(8) + `FORBIDDEN_FAMILIES` 内）。
- **由此入账的口径订正**（Spec Key Change 1 / C-37）：`ADR-195` 原文「GPU/ONNX 族 0 命中」失实——
  `Cargo.lock` 含 `tract-{core,data,hir,linalg,nnef,onnx,onnx-opl}` 7 包，且 `tract-onnx = "0.22"` 是
  `nmc-encoder` 的**现役 CPU 推理生产依赖**。GPU 否决结论不变，但证据链改写为
  「GPU 计算族与 ONNX-Runtime(`ort`) 族 0 命中；`tract` 属 CPU 推理器不在禁列」，**不扩禁列**
  （tract 无 GPU feature）。
- **实现落点**：`scripts/check_accel_exclusion.py::scan_lock()` 直调；`--selftest` 含该组夹具。

## 6. M6 — 端到端 overwindow A/B（决定 P-2 能否闭合）

- **靶标缺失的实况**：此前只有 dense **段隔离**读数，端到端无组目录 ⇒ 本批新增
  `crates/chimera-cli/benches/overwindow_bridge.rs:86` 的 `bench_e2e_dense_ab`（三语料 × 四臂，
  被测对象**自报** `block_count()`（定义在 `crates/chimera-cli/src/overwindow_bridge.rs:184`）
  与 `route()`，并附**同路质控臂**）。
- **读数**：681 / 1100 / 3684 块 → **1.375× / 1.65× / 2.57×**；而 §11 同规模 dense 段隔离读数为
  2.3–5.0× ⇒ **外推差 ≈ 49%**（判据 20%）（A 级）。
- **精度下限量化**：同路两臂差 ≤ 3.2%，但跨轮质控漂幅 0.3–16.4% ⇒ 本机已不具备标定「最优阈值」
  所需的精度（这是「阈值维持 1000」的第二条独立理由）。
- **结论**：**段测不可外推到端到端**（Spec P-2「M6 决定 P-2 是否可闭合」→ 结论为可闭合“不改阈”，
  但“改阈到多少”未闭合，需 clean-runner）。
- **自错作废项**：本轮之前我写过「阈值影响面超出 dense 段」作为不改阈的理由之一，
  该理由被 M6 自身证据推翻 ⇒ 已作废，只保留「不可外推 + 精度不足」两条实证理由。
- **登记口径（2026-10-10 现取；防下轮误判成“M6 漏了三源登记”而去补一个假阈值）**：
  Test Plan 要求“新 bench 走 P-6 三源登记（`perf_thresholds.toml` + `bench_check.yml` + 不变式），
  未实测禁入”。实况：`overwindow_bridge` 在三源**各 0 次**，而在 `scripts/bench_inventory_freeze.txt`
  有 1 行 `chimera-cli|overwindow_bridge|dev-only|overwindow 桥接开发探针，无 SLO`。
  `check_perf_redlines.py` 的判定序是四态（`gated` / `registered` / `dev-only` / **`unknown` ⇒ FAIL**），
  所以“无实测的新 bench”的**合规路径就是 dev-only 台账**（台账按文件计，本文件内新增组不需新增行，
  不变式门现 rc=0）；反之若把 M6 本机读数写进三表，同时违反本批 P-2/F-1 结论（无 clean-runner 不标定）
  与“SLO 三表零改动”纪律（详执行报告 §34.1）。
