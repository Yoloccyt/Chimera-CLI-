# =============================================================================
# dev_dep_freeze.txt - "dev-dependencies 向上边"存量基线（v3.5 C-52 / 门 G-93）
# =============================================================================
# 语义: 每行 `用户crate|被依赖crate` 登记一条**向上**的 dev 边（layer(dep) > layer(user)）。
#       方向铁律的 dev 面此前机器不可见（Check B 只读 [dependencies]），本台账 + G-93 把它
#       变成可执行判据。层号一律**派生**自唯一权威源
#       `scripts/check_dependency_rules.sh::layer_of()`（禁手抄层表，终局原则 1）。
#
# 棘轮方向: **只减不增**（与 dep_edge_freeze.txt 同族）。
#   - 新增向上 dev 边未登记  ⇒ [GAP-D] 判红；
#   - 登记行在盘上已不再向上（消边或改成同层/向下）却还留着 ⇒ [STALE] 判红，必须同批删行。
#   判据本体与两类失效由 `check_dev_dep_direction.py --selftest` 双向夹具锁住。
#
# 为什么这 2 条能进基线而不是当场修（诚实登记，不写成"已治理"）:
#   它们都是**测试/基准面借用上层实现**的既成事实，且**已各自在 Cargo.toml 里写过注释形式
#   的豁免**（W8 清理记档，见下行引用）—— C-52 定性为"注释即治理"：没有任何机器判据
#   会去核"这条注释说的东西今天还成立吗"。本台账 + G-93 就是把那句注释升成可验判据：
#   边消失而行不删 ⇒ STALE 红；新向上边不登记 ⇒ GAP-D 红。
#   v3.5 Spec 的 C-52 默认值是"做，独立 id 观察一周期"⇒ 本批评档 + 建门，不动这两条边。
#
# 观察期出口（不得长期滞留，二者择一）:
#   ① 消边：把用到的能力下沉到同层或以下，或将测试改为经公开 API 驱动；
#   ② 转正：立 ADR 定宿主语义，并同批在 `dep_edge_freeze.txt` 登记生产边 + 删本台账行。
#   若一周期后仍无 ① 或 ②，G-93 的"观察态"就应升为阻塞（接 ci.yml），因为届时留下的
#   不是"未知风险"而是"已知不处置"——这两者对下一轮建设者的含义完全不同。
# =============================================================================
