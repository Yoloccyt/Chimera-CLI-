# L0 public-type extensibility class ledger (G-115/G-116, ADR-214 decision 3 / D-22).
# Judged by scripts/check_l0_extensibility_class.py. Baseline emitted 2026-10-14 from the
# live tree: 227 production public types (103 pub enum + 124 pub struct). The raw unmasked
# grep says 228; the extra one is vector_math/vector.rs:342 `InMemoryVectorStore`, declared
# inside a #[cfg(test)] tail -- the gate's blank+tail-mask surface (shared lexer with G-99/
# G-105) is the authoritative count, and this ledger is keyed to THAT number on purpose.
#
# WHAT A ROW MEANS (this is a POLICY declaration, not a description of code):
#   class=closed  the type is extensible only by a breaking change. Downstream may match it
#                 exhaustively, so adding a variant/field forces every consumer to handle it.
#                 This is the safety property that event-bus/src/registry.rs exploits with its
#                 FIVE wildcard-free matches (a new NexusEvent variant without a severity
#                 cannot compile). Verdict / failure / severity / strategy enums want this.
#   class=open    the type carries #[non_exhaustive]; consumers must keep a catch-all arm, so
#                 L0 may add variants or fields without breaking anyone. Right for display,
#                 format, and vocabulary-like types whose value set is known to grow.
#
# THE LOCK (why a prose list would have rotted):
#   class=open   <=> the attribute is present;  class=closed <=> the attribute is absent.
#   Opening a type is therefore TWO edits in ONE commit: flip this row (with a reason of at
#   least 24 chars) AND add #[non_exhaustive]. Doing only one is CLASS_MISMATCH red. Either
#   half alone is exactly the silent drift this repository keeps getting bitten by: an
#   attribute added "to be forward compatible" quietly removes compile-forced handling from
#   every consumer, and a row flipped without the attribute makes the ledger a lie.
#   NEW public types with no row are red, and a row whose type moved/disappeared is STALE
#   red -- so a W3-style physical move must re-key rows in the same commit.
#
# CURRENT STATE: all 227 rows are closed, because L0 measures ZERO #[non_exhaustive] today
# (grep -rc over src = 0). Emitting the baseline therefore encodes no new decision; it makes
# the existing, never-declared default explicit and reviewable, so the first future opening
# is a choice someone signs rather than a side effect.
#
# OPENING SHORTLIST (decided later, per type -- deliberately NOT pre-applied here):
# 21 pub enums have zero textual mention in ANY other crate's src/tests/benches/examples and
# in the root tests/ tree, which proves no downstream match, use-path, or construction site
# exists today; marking them cannot break a single line of code. That list, plus the measured
# 64 pub structs with no external `Name {` literal, is recorded in ADR-214 (D-22) together
# with the counter-argument: zero-mention marking is compile-safe NOW but forfeits the forced
# handling for FUTURE consumers, so verdict/failure/layer types (ErrorLayer, RecoveryStrategy,
# ToolFailure, EventFailure, GateVerdict, CertifyVerdict, PlanViolation, JudgeTier) should stay
# closed even though they are on the compile-safe list.
# Scope note that changed the answer: the first scan counted only crates/*/src and reported
# 22 candidates; VerificationMethod turned out to be matched in three root tests/e2e files, so
# the downstream surface MUST include root tests/ -- otherwise the set is falsely permissive.
# emitted from the live tree; class mirrors the CURRENT attribute state,
# so every emitted row agrees with the tree by construction. Review before
# promoting to the real ledger: opening a type is a decision, not a default.
